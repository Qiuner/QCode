让用户走进小镇，找到合适的居民，把事情真正做完。

世界画面负责让人愿意走进来，居民与工作流程负责让人获得实际成果。每项功能都应帮助用户明确下一步、知道居民正在做什么、检查工作结果，并在下次回来时接着做。

核心路径：进入小镇 → 找苔伯选择项目与配置模型 → 找 Q 提出需求 → 查看执行、处理确认 → 检查成果与验证结果 → 继续修改或下次回来续接。

## 第一版 · 2026-09-11

状态：已实现并完成下述验证。

- 向导展示项目、模型、开始制作三步；选好项目后折叠文件夹操作。
- 缺少模型配置时引导填写 Key，保留未发送的需求；配置状态与连接测试结果不混淆。
- 草稿按项目和居民保存到当前浏览器；发送成功后才清除对应草稿。
- 已有对话或草稿的居民显示继续入口，恢复时复用原 Session。
- 居民面板优先展示审批和本轮进展，呈现用户请求、居民回复和真实工具返回结果；之前的对话可展开。
- 运行中补充消息会排队，关闭面板不取消任务；“本轮结束”不表示验证通过。

实现与存储边界见 [居民工作闭环](resident-work-loop.md)。

实际验证：Web 构建、类型检查、15 项居民事件与模型配置测试、diff 空白检查通过。隔离浏览器验收使用本机模拟模型和真实 DSH 运行时，覆盖缺 Key、草稿恢复、用户 Key 接入、同一会话续接、关闭面板后完成，以及项目文件 write/read 工具往返；检查了桌面与 390px 宽面板。

验证边界：上述浏览器验收替换了世界 iframe，未覆盖真实地图中的完整操作；模拟模型不证明真实模型能正确完成开发需求。草稿与居民映射不提供跨浏览器同步，Teacher / File Keeper 的只读约束目前仍是提示词约束。
