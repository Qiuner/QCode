# 小镇工作闭环施工记录

## 产品目标

让用户走进小镇，找到合适的居民，把事情真正做完。

世界画面负责让人愿意走进来，居民与工作流程负责让人获得实际成果。每项功能都应帮助用户明确下一步、知道居民正在做什么、检查工作结果，并在下次回来时接着做。

核心路径：进入小镇 → 找向导 → 选择项目与配置模型 → 找 Coder 提出需求 → 查看执行、处理确认 → 检查成果与验证结果 → 继续修改或下次回来续接。

## 第一版 · 2026-09-11

状态：已实现并完成下述验证。

- 向导展示项目、模型、开始制作三步；选好项目后折叠文件夹操作。
- 缺少模型配置时引导填写 Key，保留未发送的需求；配置状态与连接测试结果不混淆。
- 草稿按项目和居民保存到当前浏览器；发送成功后才清除对应草稿。
- 已有对话或草稿的居民显示继续入口，恢复时复用原 Session。
- 居民面板优先展示审批和本轮进展，呈现用户请求、居民回复和真实工具返回结果；之前的对话可展开。
- 运行中补充消息会排队，关闭面板不取消任务；“本轮结束”不表示验证通过。

实现与存储边界见 [居民工作闭环](resident-work-loop.md)。

实际验证：Web 构建、类型检查、15 项居民事件与模型配置测试、diff 空白检查通过。隔离浏览器验收使用本机模拟模型和真实 DSH 运行时，覆盖缺 Key、草稿恢复、用户 Key 接入、同一会话续接、关闭面板后完成，以及项目文件 write/read 工具往返；检查了桌面与 390px 宽面板。

验证边界：上述浏览器验收替换了世界 iframe，未覆盖真实地图中的完整操作；模拟模型不证明真实模型能正确完成开发需求。草稿与居民映射不提供跨浏览器同步，Teacher / File Keeper 的只读约束目前仍是提示词约束。

### 统一居民对话 · 2026-09-11

- Web 中按 E 直接进入 React 居民面板，取消重复的 Godot 固定对白；关闭后可立即与同一居民再次交谈。
- 面板状态同步到世界，清理按键与鼠标捕获，阻止误移动；切到网页面板不会触发游戏暂停菜单。
- 入场静默恢复项目，不自动弹出向导；历史记录由独立入口打开。Godot 通过 JSON 传递居民信息，修复按 E 后面板未打开的问题。职责与交互规则见 [居民对话系统](dialogue-system.md)。
- 验证：Godot 居民与嵌入 HUD 测试、7 项 Web 桥接测试、Web 构建、世界导出与中文字体检查通过；用户确认当前可正常对话。首次使用完整流程、第一人称与窄屏仍需专项验收。

### 工作记录与恢复入口 · 2026-09-11

- 进入页面先恢复项目和会话目录；已有项目展示居民工作记录、最近需求 / 回复摘要和继续入口，关闭面板后仍可返回工作记录。
- 项目选择与居民关联保存到本地 Host，浏览器存储作为旧数据迁移来源；DSH 继续持有真实会话历史。
- 区分加载、超时、恢复失败和项目失效；会话已删除或旧标题存在歧义时，不自动创建替代会话。
- 实际验证：Web 构建及 14 项居民事件 / 恢复测试通过，其中恢复测试覆盖重新创建存储处理器、并发合并、无浏览器映射恢复、旧关联迁移、已删除会话和歧义会话。
- 限制：浏览器工具认证异常，本轮未完成真实浏览器与地图视觉验收；草稿仍在浏览器本地。可靠续接阶段尚未完成全部验收，不标为完成。

| 阶段 | 要解决的问题 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| 真实任务验收 | 能连通还不等于能完成事情 | 在真实小镇与真实模型中完成一个小功能，检查文件修改、运行结果和后续修正；模型调用需使用用户认可的配置 | 待做 |
| 交付与异常反馈 | 用户能判断结果并知道失败后怎么继续 | 修改文件与验证依据便于查看；断网、模型失败、取消和拒绝工具请求后，能明确重试或继续 | 待做 |
| 居民能力边界 | 各居民有实际职责与可执行的权限限制 | Coder 能实施和验证；Teacher 能结合项目解释；File Keeper 能查找与读取；只读角色有运行时限制 | 待做 |
| 可靠续接 | 重启或恢复异常时不丢失工作关系 | 验证服务重启、项目失效、会话删除和存储不可用；提供明确恢复入口 | 待做 |
| 易用分发 | 普通用户无需配置开发环境 | 提供启动方式、就绪与失败提示，让用户能进入小镇并完成首次任务 | 待做 |
