## 加载反馈与远景

邻区状态通过 `world:regions` 同步给宿主：等待主岛、下载（显示已接收 MB）、展开、失败、开放。下载自动重试一次，失败后保留原因和重试按钮；桥口有实体栏杆及区域路牌，安装成功后一起移除。手动重试绕过旧缓存，资源头校验阻止把错误页作为 PCK 挂载。已实测注入 HTTP 503 后连续失败，再恢复网络点击重试完成加载。

远景使用 Compatibility 可用的深度与屏幕纹理后处理，按角色水平距离控制雾色和五点柔化。俯视角 10 米内保持清晰，约 32 米达到最大效果；第一、第三人称清晰范围为 7 米。跟随角色更新焦点，不影响宿主网页 UI。保留近景色彩与已有灯光，没有开启体积雾；仍有一次屏幕拷贝及采样成本，低性能设备的帧率需要后续持续观测。

## 首次交互与编译停顿排查

同机 Edge 独立浏览器实例、1440×900 的两次基准中，主岛首帧约 41–45 秒；邻区节点创建约 1.3–1.4 秒，随后首轮绘制又阻塞约 14.8–15.1 秒。WebGL `getProgramParameter` 调用记录确认主要时间用于着色器编译等待。重复刷新利用缓存后首帧约 6.8 秒，不能把热缓存结果与冷启动直接比较。拆包减少首轮传输，但没有消除编译，也会把邻区的首次绘制停顿移到玩家进入主岛之后。

首次学习箱子复现约 5.2 秒长任务，其中两次图形程序编译等待合计约 4.7 秒。预览原用受光、发光的透明 StandardMaterial3D，现改为轻量 unshaded ShaderMaterial；未预热的对照首次交互降至约 0.39 秒。最终版在启动首帧提交相同预览材质预热，并提高预览渲染优先级。

网页每物体局部灯光上限从默认 8 调为 2，当前场景只有一盏 OmniLight，方向光不受此上限影响；保持阴影品质。Web 邻区分两次安装并分别等待首帧，所有碰撞和首轮绘制就绪后才移除路障、报告 ready。该调整减少一次集中提交的工作量并修正状态时序，不代表每块区域已实现无阻塞加载；单区域同步读取、碰撞生成及驱动首次编译仍可能造成停顿。

2026-09-11 最终复测：独立 Edge 实例主岛首帧约 32.4 秒，邻区真正绘制完成约 46.2 秒；邻区两段长任务约 4.0 秒、7.7 秒。首次 E 学习提示及 F 放置截图确认成功，两次交互均未记录到超过 50 毫秒的 Long Task，WebGL 探针也未捕获超过 30 毫秒的编译等待。这是本机单次最终样本，不是跨设备性能保证。冷启动仍需后续降低场景着色器变体或调整引擎编译流程，不能宣称加载已无卡顿。

## 剩余停顿的实施方案与试验

2026-09-11 后续核验确认测试使用 ANGLE D3D11 / NVIDIA RTX 4060，而非软件渲染，浏览器提供 `KHR_parallel_shader_compile`。当前实际 WebGL 调用仍会同步等待编译结果。上游 [ShaderGLES3](https://github.com/godotengine/godot/blob/master/drivers/gles3/shader_gles3.cpp) 的 `_compile_specialization` 在链接后调用 `glGetProgramiv(GL_LINK_STATUS)`，`_initialize_version` 逐个编译变体，Web 分支禁用自身二进制着色器缓存。这是上游 master 的实现佐证，并非对本机模板源码版本的逐字核验；定制模板前必须确定匹配版本。浏览器自身可能缓存编译结果，但不能承诺其缓存命中。

追加的小规模实验（同一机器、独立 Edge、1440×900）：

| 实验 | 观测 | 决策 |
| --- | --- | --- |
| 网页局部灯光总数上限 32 → 4 | 主岛首帧 32.1 → 30.8 秒；只测一组，无法排除波动 | 撤回实验配置，不作为主要方案 |
| 单份真实灯光程序关闭复杂高光 | 编译 1825 → 1059 毫秒，两份程序均编译成功 | 值得做哑光材质试点；不等于全场景已有同等加速 |
| 同一程序方向灯数组 8 → 2 | 1825 → 1855 毫秒 | 不采用 |

### 1. 先做网页哑光材质试点

- 目标：减少受光程序的复杂度和不同特性组合，避免每块地图都首次编译一批复杂变体。
- `assets/streamside_vertex.gdshader`、`assets/desert_sand.gdshader` 先各选一个试点：保留顶点色、沙丘渐变、环境光和阴影，验证轻量漫反射及关闭复杂高光的视觉影响。
- 试点有效后，再在 `scripts/island.gd` 的模型材质配置及 `_material` 中统一哑光特性；颜色继续作为参数，不为每种颜色生成不同着色器。水面、金属、发光物单独保留必要特性。
- 同样特性的材质共享本身并不保证减少编译：必须记录实际不同程序及冷编译耗时。不能把所有物体改成无光照材质，也不能用静态截图替代可交互地图。
- 验收：同一显卡和视口，独立浏览器实例至少三轮与当前基线比较；记录首帧、最长长任务、邻区可交互时刻及编译等待。比较相同相机位置的近景、庭院、水面和高台截图后再推广。先争取将首轮编译总耗时减半，作为实验目标而非承诺。

### 2. 将运行时碰撞生成移到构建阶段

- `tools/build_web.ps1` 在导出前调用专用 Godot 构建脚本，按来源网格生成碰撞资源并校验对应关系。
- `scripts/island.gd`、`scripts/desert.gd`、`scripts/streamside.gd` 加载预生成资源，替换 `create_trimesh_shape()`；第一步保留原几何精度，之后再独立评估简化网格。
- 验收包括相机遮挡、坡道、桥面、跳跃和箱子放置；不得以丢失碰撞换启动速度。记录包体积变化，避免以明显增大下载量换取有限 CPU 收益。
- 这一步针对 CPU 创建成本，不会自动消除 WebGL 首次编译停顿。

### 3. 最后处理编译调度与区域显现

- 材质试点仍不足时，再评估匹配版本的定制 Godot Web 模板：提交编译、通过 `KHR_parallel_shader_compile` 检查完成、完成前跳过依赖该程序的绘制；资源销毁、失败回退与不支持扩展的浏览器都要处理。不能在网页上伪造编译成功结果，也不能只加一个 Promise 就宣称异步。
- 有了实际异步完成信号，区域才适合采用低细节远景占位，后台准备完成后通过已有雾效过渡到完整场景；碰撞准备完成前继续保留桥口保护。
- 启用线程版导出或 Worker 需要跨源隔离及 SharedArrayBuffer 等条件，并不天然解决图形驱动同步编译；不作为当前最短路径。

以上为试验前的方案，落地结果与未采用的步骤记录如下。下载压缩、失败重试继续保留，不新增引擎依赖。

## 网页轻量光照实测（2026-09-11）

最终实现由 `scripts/web_rendering.gd` 在首轮绘制前处理主岛、邻区和新放置的木箱。StandardMaterial3D 统一将 Burley 漫反射替换为 Lambert，保留高光模式、金属度、透明度、发光及纹理参数；不处理无光照或已有其他漫反射模式的材质。沙丘与庭院的两份自定义哑光着色器使用 Lambert 并关闭高光。变体按来源资源共享，不修改导入的原始资源。网页默认启用，原生版只有传入 `--web-lightweight` 才启用。

最初试验仅对粗糙表面关闭高光，但保留的光滑表面仍需要完整程序，程序链接次数从 103 增至 110，主岛有样本反而变慢，因此撤回了这条路径。最终方案统一 StandardMaterial3D 的漫反射模式，程序链接次数保持 103。链接次数是 WebGL 探针的调用计数，不是对所有源代码做哈希去重后的变体数。

同机 Edge headless / ANGLE D3D11 / RTX 4060、1440×900，交替启动全新浏览器进程，最终版与 `--full-materials` 基线各取得三个有效样本。一轮基线出现 iframe 断开，已剔除并补测；不能把它算作成功加载。测试中的路由回调在页面关闭前解除，避免在途请求取消造成测试进程的未处理异常。

| 指标 | 基线（三次，秒） | 最终版（三次，秒） | 中位数结论 |
| --- | --- | --- | --- |
| 主岛首帧 | 34.894 / 34.599 / 34.687 | 34.676 / 34.807 / 34.235 | 34.687 → 34.676，基本持平 |
| 邻区全部开放 | 49.757 / 49.708 / 49.678 | 46.750 / 48.044 / 45.873 | 提前约 3.0 秒（6.0%） |
| 主岛开放后的最长长任务 | 8.401 / 8.477 / 8.518 | 7.027 / 8.013 / 6.740 | 8.477 → 7.027，减少约 17.1% |
| `getProgramParameter` 累计等待 | 40.557 / 40.155 / 40.186 | 37.678 / 38.658 / 36.608 | 减少约 6.2% |

复测辅助函数为 `packages/agent-isles-web/tests/world-startup.mjs` 的 `measureWorldStartup(browser, authenticatedUrl, options)`；调用方提供 Playwright、新浏览器进程与本机认证 URL。`fullMaterials: true` 只在测试拦截的启动 HTML 中传入基线参数，不改变服务端导出文件。该辅助函数测量真实首帧、邻区开放、长任务和编译等待，不能用热刷新替代上述冷启动流程。

精确碰撞离线化也做了小规模试验：主岛 531,618 个三角形现场生成约 1.24 秒，读取预保存的压缩碰撞资源仍需约 0.85 秒，并新增约 4.13 MB 资源文件。该文件大小不是额外 HTTP 传输量的实测值。收益不足以抵消包体及构建复杂度，未加入正式构建；后续应单独评估简化相机碰撞网格，而非仅序列化原始网格。

此次另外核对了本机模板对应的精确版本：`ed1daf0bf/version.py` 为 4.7.2 stable。[同版本 ShaderGLES3](https://github.com/godotengine/godot/blob/ed1daf0bf/drivers/gles3/shader_gles3.cpp#L427) 在链接后立即查询 `GL_LINK_STATUS`，Web 分支仍不读取引擎的二进制程序缓存。当前 PATH 未找到 Emscripten/SCons，本轮没有构建自定义模板。显著缩短主岛冷启动仍需继续削减必要着色器的复杂度，或建立匹配版本的异步编译模板；网页层分帧不能解除驱动的同步等待。

最终代码的材质参数保留、共享及幂等测试通过；使用 `--web-lightweight` 的相机、分区安装、浇水收纳和箱子玩法测试通过，Web 导出成功。检查了真实网页默认视角，并用原生 Compatibility 渲染器对主岛、庭院、沙漠、讲台、水池五个固定机位进行前后对照：受光表面的明暗略有变化，未发现材质丢失；水面高光、阴影、远景雾效保留。固定机位对照不等于已经覆盖所有浏览器、相机角度和设备。

该轮改善主要在邻区首次显示，未达到首轮编译减半的实验目标，也没有消除数秒级停顿。
