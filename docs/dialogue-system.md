## 单一入口与事实来源

用户靠近居民按 E，或从工作记录选择居民，打开同一个 React 居民面板。Web 世界不再同时显示 Godot 的固定对白框。向导负责项目选择、恢复与引导；制作、教学和文件居民接入各自的真实 Session。DSH 是消息、执行、审批和结果的事实来源。

| 层 | 职责 |
| --- | --- |
| Godot | 居民位置、靠近提示、选中事件、人物工作状态 |
| React | 当前交谈对象、项目引导、输入草稿、对话历史、审批和结果呈现 |
| DSH / Host | Workspace、Session、执行记录、权限与持久化关联 |

## 交互规则

- 加载封面期间不显示居民面板、工作入口或邻区提示。`world:ready` 只表示消息桥可用；世界启动完成并收起封面后发出 `world:playable`，React 才显示入口。默认不选中居民、不打开面板、不接管焦点；项目在后台静默恢复，不自动执行任务，也不等待邻区全部加载。
- 顶部项目入口负责切换项目，工作记录入口主动打开独立的记录视图（桌面为侧栏，小屏为底部面板）。欢迎对话不嵌入历史列表；无任务且无草稿的居民不占记录卡片，原始回复和错误在完整会话中查看。首次交谈先选择制作或认识居民，再按需选择文件夹。
- 世界发出 `resident:selected`，React 决定打开居民或先引导恢复项目。Godot → JavaScript 的载荷先序列化为 JSON 字符串，再由网页桥解析，避免 Dictionary 无法跨语言传递而丢失居民编号。
- React 通过 `world:init.payload.panelOpen` 同步面板状态，包括模型设置。Godot 清理旧对白、释放鼠标与按键、停止角色移动并隐藏交谈提示；环境动画继续。
- 关闭面板后恢复世界操作，可以立即再次与同一居民交谈。关闭、走远和切换居民不取消后台任务；取消任务仍是独立操作。
- Web 中焦点切到面板不弹出游戏暂停菜单。独立运行 Godot 时保留探索对白与原暂停行为。
- 向导文案从项目和会话状态生成：首次选择、继续已有项目、正在工作或等待确认。固定的接待文案不冒充模型回复，也不推断未经验证的任务成功。
- 完整对话只保留一份。世界可以展示状态提示，但不再维护第二套工作对话、历史或审批。
