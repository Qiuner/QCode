# 文档维护指南

## 文档类型

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| Guide | 面向用户或开发者的操作路径 | 岛屿与插件开发指南 |
| Contract | 必须遵守的边界、接口和状态语义 | 岛屿接入契约 |
| Architecture | 跨领域职责和长期结构 | 总体架构 |
| Plan | 尚未完成的实施步骤 | 世界网页实施方案 |
| Evidence | 已执行的测试、截图和复现材料 | `docs/evidence/` |
| Decision | 已采用方案及原因 | `.agents/notes/implemented/` |

## 状态标记

施工和专项文档统一使用：`待实施`、`实施中`、`已实现待验收`、`已验收`。契约文档描述目标约束时，必须在开头说明哪些条款尚未落实；不能用“已验收”替代实际证据。

## 更新规则

- 架构文档只写职责、生命周期、数据、接口和事件，不记录施工流水账。
- 契约发生变化时，同步更新总架构中的链接和相关专项文档。
- 测试命令、截图和复现日志放入专项计划或 `docs/evidence/`，并注明日期与范围。
- README 只保留使用入口和稳定链接，不复制施工进度。
- 新增文档必须从 [文档入口](README.md) 可达。
