# 维护决策：教程复用 Cordis 与 DSH 基础设施

状态：已采用，尚未实施；自定义 Remote、存储 profile 和执行接口需接入验证。

## 问题

继续增加手写存储、独立事件总线和 Session 包装会重复已有设施。直接套用 Koishi 或假定 Cordis 事件自动跨端传播，也不符合固定版本 DSH 的接口。

## 决定

- 以固定版本 `@deepseek-ai/cordis` 的公开接口管理服务、依赖与资源生命周期；课程和项目作为数据，不各自创建插件。
- agent-isles 拥有教程定义、学习记录、验收和居民关联；DSH 继续拥有会话、工具、审批和执行历史。
- 学习记录优先采用 DSH `storage.domain`；业务输入校验、并发约束、迁移和跨操作恢复由 agent-isles 实现。
- 核心操作直接等待服务调用与持久化，进程内事件只通知已确认的变化。
- 跨端优先验证 DSH Remote/Typert 的扩展；不修改上游事件白名单，不重复注册全局 Remote 事件源。必要时用窄快照接口和有界轮询交付首版。
- 按能力分离依赖；模型不可用不阻止读取教程与学习进度。

## 后果

减少自建基础设施，但需要承担固定版本兼容验证。存储域不自动提供跨 DSH 操作的事务；Cordis 不自动取消任意异步任务。已有居民恢复逻辑按独立变更迁移，不要求首课同时完成全面重构。

具体接口、证据与退路见 [教程架构](../../../../docs/tutorial-architecture.md)。
