# 维护决策：教程内容与执行信任边界

状态：已采用，尚未实施。

## 问题

教程可能携带模板和检查要求。若将课程脚本作为 Host 插件直接加载，就将内容来源提升为本机程序权限；代码签名或 Cordis Context 隔离不能替代执行权限控制。

## 决定

- 首版教程采用声明式定义、模板与资源，检查类型由官方可信代码实现；不允许教程包携带任意 Host 可执行插件。
- 模板复制必须限制目标路径并保护已有作品。
- 项目测试与构建视为代码执行，经 DSH 的权限、审批及可用沙箱能力运行，配合超时、输出限制和取消。
- 固定 runtime 缺少必要能力时缩小检查范围，不绕过审批直接在 Host 执行。
- 签名、发布包完整性验证与操作系统进程管理属于发布流程和未来 Launcher；独立子进程本身不等于安全沙箱。

## 后果

首版课程扩展能力受预定义检查类型约束，但信任边界清晰。未来引入第三方可执行扩展需要新的权限、隔离、兼容与分发设计，不视为普通教程格式扩展。

范围与待验证项见 [教程架构](../../../../docs/tutorial-architecture.md)。
