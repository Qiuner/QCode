# 本地服务托管

构建后执行 `node apps/web/src/background.mjs start`，将小岛服务放入独立、无窗口的后台进程。终端关闭后服务继续运行；重复执行会复用同一数据目录对应的托管进程。启动后使用根目录「打开小岛.cmd」进入。

- 状态：`node apps/web/src/background.mjs status`
- 停止：`node apps/web/src/background.mjs stop`
- 前台开发仍可使用 `corepack yarn dev:web --no-open`，Ctrl+C 表示主动停止，不触发重试。

不要同时运行前台服务和后台托管；切换前先停止原入口。状态命令报告托管进程存活，不等同于 HTTP 就绪。

开发与桌面启动器共用 `launch.mjs` 的服务托管：异常退出后等待 1、3、10 秒重试，连续失败超过三次后停止；运行满五分钟后重置重试预算。正常退出、主动停止不会重启。首次分配的端口在本次托管生命周期内保持不变，重试不会重复打开浏览器或提交任务。

日志默认在 `.agent-isles-home/service.log`，记录启动、输出、退出码、信号和重试原因；超过 5 MiB 保留上一份。启动链接中的令牌会脱敏，当前可用入口单独保存在 `browser-url.txt`。后台引导错误写入 `background.log`。桌面继续使用自己的数据目录与 Windows Job Object 管理完整进程树。

客户端使用 DSH 已有自动重连和会话同步，并显示断线提示。本实现不自动重试业务任务，也不因请求变慢强杀服务；无响应但未退出的进程需要人工检查日志。开发托管进程本身被系统终止后的恢复、系统重启后自启动不在本次范围内。
